# 理由への反論機能 — デザインスペック

記録日: 2026-08-16  
関連: `docs/ideas.md`（優先1「理由への反論だけを許す」）

## ゴール

お題への意見投稿に対し、**理由1・2・3のどれか1つ**への反論だけを許す。反論も意見投稿と同じく「反対の主張＋理由3つ」必須。議論を「人への反対」ではなく「理由の弱さへの指摘」に寄せる。

## 非ゴール（このスコープ外）

- 投稿全体への返信・自由コメント
- 反論への反論（ネスト2段以上）
- いいね・ログイン必須
- 賛成/反対の明示ラベル、締切後の結論ページ

## 確定したルール

1. **対象単位:** 反論は `post` の `reason_index`（1 / 2 / 3）に紐づく。投稿全体への返信は禁止。
2. **深さ:** 1段のみ。`rebuttals` への反論は作らない。
3. **形式:** 反対の主張（`claim`）＋理由3つ。すべて必須。
4. **1度だけ:** 同じ `nickname` は、同じ投稿の同じ理由に対して反論を1回まで。
5. **自己反論不可:** 元投稿と同じ `nickname` では反論できない。
6. **複数人:** 別ニックネームなら、同じ理由に複数の反論を付けられる。
7. **本人識別:** 現状どおりニックネーム＋localStorage。厳密な本人認証はしない。

## アーキテクチャ

既存の `posts` はそのまま。反論は専用テーブル `rebuttals` を新設する。

お題ページで:

1. `topics` / `posts` を取得（現行どおり）
2. 取得した `post.id` 群で `rebuttals` を一括取得
3. UI上で各投稿の理由1・2・3の下に、該当する反論をぶら下げる

クライアントは引き続き Supabase anon クライアント（`src/lib/supabase.ts`）を使う。認証導入はしない。

## データモデル

### テーブル `rebuttals`

| カラム | 型 | 制約 | 意味 |
|---|---|---|---|
| `id` | uuid | PK, default gen_random_uuid() | ID |
| `post_id` | uuid | NOT NULL, FK → posts(id) ON DELETE CASCADE | 元投稿 |
| `reason_index` | smallint | NOT NULL, CHECK (reason_index IN (1, 2, 3)) | 対象理由 |
| `nickname` | text | NOT NULL | 反論者 |
| `claim` | text | NOT NULL | 反対の主張 |
| `reason1` | text | NOT NULL | 反論の理由1 |
| `reason2` | text | NOT NULL | 反論の理由2 |
| `reason3` | text | NOT NULL | 反論の理由3 |
| `created_at` | timestamptz | NOT NULL, default now() | 作成日時 |

### インデックス / UNIQUE

- UNIQUE (`post_id`, `reason_index`, `nickname`) — 同じ人による同じ理由への二重反論を防ぐ
- INDEX (`post_id`) — お題ページでの一括取得用

### アプリ側バリデーション（DB UNIQUEに加えて）

挿入前に:

1. `claim` / `reason1` / `reason2` / `reason3` / `nickname` が空でない
2. `reason_index` が 1・2・3 のいずれか
3. 元投稿の `nickname` と反論者の `nickname` が一致しない（自己反論禁止）

自己反論は DB だけでは表現しにくい（posts を JOIN するトリガーが必要）ため、MVP ではクライアント＋挿入前チェックで担保する。UNIQUE は二重投稿の防止に使う。

## UI（お題ページ `src/app/topics/[id]/page.tsx`）

### 投稿カード

- 既存: ニックネーム、日時、意見、理由1・2・3
- 追加: 各理由ブロックの下に、その理由への反論一覧（インデント）
- 各理由に「この理由に反論」アクション

### 反論フォーム

- 対象理由を選んだときだけ開く（インラインまたは下部シート。既存の「意見を書く」の固定ボトムフォームに合わせる）
- 見出し例: 「理由2への反論」
- フィールド: ニックネーム / 反対の主張 / 理由1 / 理由2 / 理由3
- 送信成功後: フォームを閉じ、一覧を再取得（またはローカルに追記）して表示更新
- ニックネームは既存どおり localStorage に保存・復元

### ボタン表示条件

| 状態 | UI |
|---|---|
| 保存ニックネームが元投稿と一致 | 「この理由に反論」を出さない |
| 同じ理由に自分の反論が既にある | ボタンを出さない、または「反論済み」 |
| それ以外 | 「この理由に反論」を表示 |

### コピー（文言）

- ボタン: 「この理由に反論」
- 送信: 「反論する」
- 二重投稿: 「すでにこの理由に反論済みです」
- 一般失敗: 「反論の投稿に失敗しました」

## エラー処理

| ケース | 挙動 |
|---|---|
| 必須欠落 | 送信前アラート（既存投稿と同様） |
| 自己反論 | ボタン非表示。送信されても拒否してメッセージ表示 |
| UNIQUE 違反（二重反論） | 「すでにこの理由に反論済みです」 |
| その他 DB エラー | 「反論の投稿に失敗しました」＋ console.error |

## 手動確認チェックリスト

1. 理由1・2・3それぞれに反論を付けられ、claim＋理由3つが必須である
2. 同じニックネームで同じ理由に2回目が送れない
3. 自分の投稿には反論ボタンが出ない
4. 反論の下にさらに反論 UI が出ない
5. 別ニックネームなら同じ理由に複数反論できる
6. お題ページ再読み込み後も反論が表示される

## 成功条件

お題ページで、他人の投稿の各理由に対し「反対の主張＋理由3つ」の反論ができ、自己反論・二重反論・ネストが起きないこと。既存の意見投稿フローは壊さないこと。
